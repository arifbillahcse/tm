# Development instructions
Read docs/PROJECT_OVERVIEW.md, FEATURES.md, ARCHITECTURE.md, DATABASE.md, SECURITY.md, ROADMAP.md and DEVELOPMENT_STATUS.md before changes. Work one phase at a time; inspect existing files first. Use PHP 8.3, Laravel 12, MySQL 8, Blade/Livewire/Alpine/Tailwind; verify dependencies before pinning. Prefer modular monolith, Laravel conventions, typed PHP, form requests, policies, service classes for complex domain logic, migrations and factories. No mandatory paid services. Use workspace-scoped queries and explicit authorization for every record, including jobs, exports, search and attachments. Never commit secrets or real user data. Add regression and cross-workspace tests for every sensitive feature. Keep UI responsive and accessible; use reusable components and translated labels. Store UTC, display user timezone. Use feature branches from develop; descriptive commits; review changes and CI before merging; main is stable. Never force push. Update status with actual tests and blockers, not assumed success. Do not deploy without owner approval. If GitHub-only execution is used, rely on CI for runtime validation and report limitations. Do not introduce subscriptions or public registration without explicit approval.
