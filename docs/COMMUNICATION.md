# Phase 16 communication and integrations
Business conversations are participant-only, even for owners/admins. Direct conversations deduplicate by sorted participant IDs; groups have fixed membership. Current workspace membership is required for reading/writing and notification delivery. Mentions are explicit participant selections. Announcements reuse the existing team feature and notify active recipients. Notifications are recipient-specific with read tracking, mentions-only preference and opt-in generic email alerts. Email scheduler communication:tick sends at most 30 pending alerts per tick, only when COMM_EMAIL_ENABLED=true; SMTP must be configured separately. No private message content is sent; delivery failures and interrupted sending require manual operations review. Push preference is stored but browser subscriptions and delivery are not implemented. WhatsApp generates a manual draft link only; no automatic sending.

Integration settings are business owner/admin only, secrets encrypted with Laravel APP_KEY, excluded from validation session flash and never displayed. Disabled by default; COMM_INTEGRATIONS_ENABLED=true plus explicit enable required. Telegram, Gmail, Google Calendar, Drive, GitHub use manually supplied token connectivity checks against fixed provider endpoints; RSS checks public HTTPS XML with bounded non-network parsing. These are connection tests, not OAuth authorization/refresh, synchronization, sending or feed import. WHMCS is a custom signed webhook receiver, not native WHMCS API integration. Disconnect erases credentials locally but does not revoke provider tokens; use a new label to register replacement credentials. No automatic external requests from user messages. HTTPS transport validates DNS IPv4 global addresses, pins IP, disables redirects/proxies, verifies TLS, limits response bytes and timeout. Operator must enforce network egress controls; DNS timeout depends on OS.

Webhook POST /integrations/webhook/{id}: X-Workspace-Timestamp unix seconds within 300 seconds, X-Workspace-Signature lowercase hex HMAC-SHA256 of timestamp + '.' + exact raw body using shared secret (min32 characters). JSON event_id and event_type restricted identifiers. Max64KiB body; rate-limited; duplicate event IDs with same raw payload idempotent, conflicting payload rejected. Store hash and event metadata only; notify integration owner. No arbitrary webhook actions. Native provider signatures require separate adapters. Use HTTPS and reverse proxy request-size limits. Tests mock external network; no live provider verification, OAuth, push, automatic cross-module alerts other than messages/announcements/webhooks, realtime sockets, message edits/deletion, group membership changes, browser/load/pentest or production deployment.
